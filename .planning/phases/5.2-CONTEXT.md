## 1. Executive Objective
Design and implement a generic, reusable clinical patient schema and generate a comprehensive suite of 50 synthetic prior authorization test cases across the 10 selected CPT codes based directly on `Policy_Ground_Truth.xlsx`.

---

## 2. Locked Decisions

### Decision 1: Case Volume & Archetype Distribution
- **Total Test Cases:** Exactly 50 synthetic test cases (~5 cases per CPT across the 10 CPT codes).
- **8 Mandatory Test Case Archetypes Covered:**
  1. `All Criteria Met`: Patient satisfies every clinical, diagnostic, and documentation rule (Expected: `MET`).
  2. `One Criterion Failed`: Exactly one criterion fails (e.g., only 3 weeks PT instead of 6 weeks) (Expected: `NOT MET`).
  3. `Information Missing`: One critical piece of clinical evidence is omitted from records (Expected: `UNKNOWN` / `INCOMPLETE`).
  4. `Wrong Condition / Indication`: Procedure requested for an unapproved or axial-only condition (Expected: `NOT MET`).
  5. `Boundary Condition`: Numerical threshold testing (e.g., exactly 6 weeks vs 5 weeks vs 6 weeks + 1 day; translation 3.5mm vs 3.0mm; >6 months vs 5 months) (Expected: `MET` / `NOT MET`).
  6. `Exception / Urgent`: Patient triggers an urgent/emergent bypass (e.g., progressive neurological deficit, cord compression myelopathy) waiving conservative care / nicotine cessation (Expected: `MET`).
  7. `Conflicting Evidence`: Two documents contain discordant findings (e.g., clinic note reports severe radiculopathy, but MRI report shows normal spinal alignment with no nerve root compression) (Expected: `REVIEW` / `CONFLICT`).
  8. `Missing Document`: Clinical requirement is described in notes, but the mandatory formal supporting report (e.g., formal dynamic flexion/extension X-ray or cotinine lab report) is absent (Expected: `UNKNOWN` / `MISSING DOCUMENT`).

### Decision 2: Artifact Structure & Storage
- **Primary Excel Workbook:** `data/synthetic_cases/Synthetic_Test_Cases.xlsx`
  - Sheet 1: `Case_Level` (11 columns as specified in Checklist lines 341–364):
    `Case ID`, `Payer`, `Policy ID`, `CPT`, `Procedure`, `Condition`, `Test Case Type`, `Expected Overall Result`, `Expected Missing Information`, `Expected Exception`, `Notes`
  - Sheet 2: `Criterion_Level` (6 columns as specified in Checklist lines 375–388):
    `Case ID`, `Criterion ID`, `Criterion`, `Expected Result` (`MET`/`NOT MET`/`UNKNOWN`), `Patient Evidence`, `Notes`
- **Machine-Readable Clinical Cases:** `data/synthetic_cases/cases/<Case_ID>.json`
  - Generic patient JSON schema containing:
    `patient_id`, `demographics` (age, sex), `diagnoses`, `symptoms`, `symptom_duration`, `clinical_findings`, `treatments`, `medications`, `imaging`, `labs`, `procedures`, `documents`
- **Clinical EHR Documents Directory:** `data/synthetic_cases/documents/<Case_ID>/`
  - Standalone clinical narrative documents for each case:
    - Physician Consultation Note (`physician_note.txt`)
    - Radiology Reports (`mri_report.txt`, `xray_report.txt`)
    - Physical Therapy Progress Notes (`pt_notes.txt`)
    - Laboratory Report (`lab_report.txt`, e.g. urine cotinine)

### Decision 3: Clinical Text Generation
- **LLM-Assisted Generation with Strict Ground-Truth Anchoring:**
  - Case metadata and expected results are derived **deterministically** from `data/ground_truth/Policy_Ground_Truth.xlsx`.
  - Narrative clinical documents are drafted using LLM prompt constraints (using existing project LLM clients such as Groq / Ollama / OpenAI) with realistic clinical vocabulary, physical exam findings, and timestamps.
  - Ensures realistic EHR style while maintaining deterministic mathematical test expectations.

### Decision 4: Schema Purity & Independence
- Generic patient schema must remain completely payer-agnostic and policy-agnostic.
- The policy criteria from `Policy_Ground_Truth.xlsx` are used to configure the test inputs and expected outputs, but are **never leaked** into the patient record as pre-digested answers.

## 3. Scope of Downstream Planning (`5.2-PLAN.md`)
The downstream planner for Phase 5.2 must:
1. Define the generic patient Pydantic/dataclass schema (`src/schemas/patient_schema.py` or `scripts/patient_schema.py`).
2. Build the synthetic case matrix mapping 50 cases across the 10 CPTs and 8 test types.
3. Build the LLM-assisted document generator script (`scripts/generate_synthetic_cases.py`).
4. Generate `data/synthetic_cases/Synthetic_Test_Cases.xlsx` with both `Case_Level` and `Criterion_Level` sheets.
5. Generate all individual JSON cases and clinical text documents.
6. Build a validator script (`scripts/verify_synthetic_cases.py`) checking schema conformance, distribution balance, and expected result consistency.
