# Phase 5.4 Context: Automated Comparison Engine & Reporting Suite (`PA_Test_Results.xlsx`)

**Phase:** 5.4 (Part 4 and Part 6 of 3-Week Technical Task Checklist)  
**Status:** Discussed & Decisions Locked  
**Created:** 2026-09-30  

---

## 1. Executive Objective
Build an automated evaluation and comparison engine (`scripts/compare_test_results.py`) that reconciles actual Prior Authorization pipeline execution outputs (`data/test_runs/latest/system_run_results.json`) against the Ground Truth answer keys (`data/synthetic_cases/Synthetic_Test_Cases.xlsx` and `data/ground_truth/Policy_Ground_Truth.xlsx`), generating the primary deliverable workbook `data/results/PA_Test_Results.xlsx` with Case-level and Criterion-level sheets, and calculating comprehensive performance metrics (Accuracy, Sensitivity, Specificity, F1, and Citation Precision).

---

## 2. Locked Decisions

### Decision 1: Input Data Sources
The comparison engine reads three verified artifacts:
1. **Actual System Results:** `data/test_runs/latest/system_run_results.json` (50 cases from Phase 5.3 execution).
2. **Ground Truth Test Cases:** `data/synthetic_cases/Synthetic_Test_Cases.xlsx` (`Case_Level` sheet and `Criterion_Level` sheet).
3. **Policy Ground Truth:** `data/ground_truth/Policy_Ground_Truth.xlsx` (`Policy_Rules` sheet for exact rule metadata and expected citations).

### Decision 2: Matching Logic & PASS/FAIL Rules
- **Overall Case-Level Evaluation:**
  - `Ground Truth == MET`: System `MET` -> **PASS**, any other -> **FAIL** (False Negative)
  - `Ground Truth == NOT MET`: System `NOT MET` -> **PASS**, System `MET` -> **FAIL** (False Positive)
  - `Ground Truth == CONFLICT` (Archetype 8): System `CONFLICT` -> **PASS**, any other -> **FAIL**
  - `Ground Truth == UNKNOWN` (Archetypes with missing critical records): System `UNKNOWN` or `NOT MET (due to missing records)` -> **PASS**, System `MET` -> **FAIL**
- **Criterion-Level Evaluation:**
  - System criterion result matches Ground Truth status -> **PASS**, discrepancy -> **FAIL**

### Decision 3: Error Classification Taxonomy
For every discrepancy or failure, the engine classifies the root cause into a standardized error type:
- `RETRIEVAL_ERROR`: Policy criteria or section missed during RAG lookup.
- `CLINICAL_REASONING_ERROR`: System misinterpreted clinical severity, duration, or diagnostic finding.
- `CONFLICT_DETECTION_ERROR`: System failed to detect discordant clinical statements or falsely flagged a conflict.
- `MISSING_EVIDENCE_ERROR`: System failed to identify missing mandatory clinical documentation.
- `CITATION_ERROR`: Policy page citation or section code inaccurate or missing.

### Decision 4: Deliverable Workbook Layout (`PA_Test_Results.xlsx`)
The workbook must contain 3 formatted sheets:
1. **`Case_Level_Results`**:
   - `Case ID`, `Payer`, `CPT`, `Condition`, `Test Case Type`, `Ground Truth Overall Result`, `System Overall Result`, `Overall PASS/FAIL`, `Runtime (s)`, `Notes/Failure Summary`
2. **`Criterion_Level_Results`**:
   - `Case ID`, `Criterion ID`, `Ground Truth Criterion Result`, `System Criterion Result`, `Criterion PASS/FAIL`, `System Evidence`, `Policy Citation`, `Patient Citation`, `Error Type`, `Notes`
3. **`Summary_Metrics`**:
   - Executive scorecard with formatted KPI cards: Total Cases, Passed Cases, Failed Cases, Overall Accuracy, PA Determination Accuracy, Sensitivity, Specificity, False Positive Rate, False Negative Rate, Criterion Accuracy, Citation Precision.

### Decision 5: Audit & Integrity Verification
- An independent verification script `scripts/verify_results_workbook.py` must validate that `PA_Test_Results.xlsx` adheres to all schema requirements, has exactly 50 case rows, matches all 170 criteria rows, and contains no missing values in mandatory columns.
