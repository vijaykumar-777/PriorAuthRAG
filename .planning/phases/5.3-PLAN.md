# Phase 5.3 Plan: Production-Like Testing Runner Harness & Batch Execution Pipeline

## 1. Executive Summary & Objective

Build and execute a production-like automated testing runner harness (`scripts/run_pa_test_harness.py`) that feeds all 50 synthetic patient cases (`SYN-001` to `SYN-050`) through the Prior Authorization pipeline under real-world clinical conditions.

The harness evaluates each case blindly (strictly isolated from `Policy_Ground_Truth.xlsx` and `Synthetic_Test_Cases.xlsx` answer keys), executing policy retrieval from `Cigna_ACDF.pdf` and clinical evidence determination across all submitted patient EHR documents.

---

## 2. Locked Context & Invariants

From [`.planning/phases/5.3-CONTEXT.md`](file:///home/vijaykumar/Desktop/project2/.planning/phases/5.3-CONTEXT.md):
- **Zero-Answer-Key Isolation Invariant:** The test harness and pipeline must receive only real-world EHR inputs: Payer (`Cigna`), CPT code, Condition, and submitted clinical documents. Expected determinations (`MET`/`NOT MET`/`UNKNOWN`) and ground-truth answer keys are strictly walled off.
- **2-Stage Evaluation Architecture:**
  1. *Stage 1 (Policy Retrieval):* Queries the hierarchical RAG pipeline (`retrieval-hierarchical.py`) to retrieve official coverage policy criteria from `Cigna_ACDF.pdf`.
  2. *Stage 2 (Clinical Evidence Determination Engine):* Compares the patient's submitted EHR notes (`physician_note.txt`, `mri_report.txt`, `xray_report.txt`, `pt_notes.txt`, `lab_report.txt`) against the retrieved policy rules to evaluate each criterion individually.
- **Checkpointing & Resumability:**
  - Cases saved immediately to `data/test_runs/latest/cases/<Case_ID>.json`.
  - Resumable: completed cases are automatically skipped if the script is restarted.
  - Master run ledger saved to `data/test_runs/latest/system_run_results.json`.
- **Throttling & Resilience:**
  - 1.5s adaptive delay between LLM calls.
  - Automatic exponential backoff retry handler for Groq API HTTP 429 rate limits.
  - Multi-tier JSON extraction & repair.

## 3. Work Breakdown & Implementation Tasks

### Wave 1: Runner Harness & Clinical Determination Engine

#### Task 1: Build Production-Like Test Runner Harness
- **File:** `scripts/run_pa_test_harness.py`
- **Actions:**
  1. Import pipeline components from `retrieval-hierarchical.py`:
     - `check_master_table_prior_auth` (Stage 1 lookup)
     - `route_query_to_toc` (Stage 2 router)
     - `retrieve_scoped_chunks` (Stage 3 scoped hybrid retrieval)
     - `registry` (Document registry)
     - `call_llm` / Groq client with retry handler
  2. Implement patient case reader loading `SYN-XXX.json` and assembling clinical narrative texts from `data/synthetic_cases/documents/SYN-XXX/`.
  3. Implement Stage 2 Clinical Determination Prompt:
     - Feeds the retrieved policy chunks + patient's actual EHR text.
     - Instructs LLM to evaluate whether each policy criterion is `MET`, `NOT MET`, `UNKNOWN` (missing evidence), or `CONFLICT` (discordant evidence).
     - Mandates extracting exact verbatim patient evidence citations and policy section citations.
     - Computes `system_overall_result` (`MET`, `NOT MET`, `UNKNOWN`, `CONFLICT`).
  4. Implement sequential loop with live progress output, error handling, rate-limit backoff, and per-case disk checkpointing.
  5. Save individual case results to `data/test_runs/latest/cases/<Case_ID>.json` and compile master `data/test_runs/latest/system_run_results.json`.

  - Assert zero ground truth answer key leakage into runner inputs.
  - Report runtime statistics and determination distribution.
