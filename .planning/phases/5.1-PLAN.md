# Phase 5.1 Plan: Ground Truth Specification & Manual Dataset Creation

## 1. Executive Summary & Objective

Establish an authoritative, human-verified ground-truth dataset (`data/ground_truth/Policy_Ground_Truth.xlsx`) based strictly on `Cigna ACDF (CMM-601)` without using LLMs for ground truth generation.

This ground truth serves as the gold standard for the entire 3-week Prior Authorization validation framework, against which all synthetic test cases (Phase 5.2), pipeline runs (Phase 5.3), and automated evaluation metrics (Phase 5.4) will be evaluated.

## 3. Mandatory 15-Column Schema

The generated workbook must strictly adhere to the schema specified in [`Task Description and Checklist.md`](file:///home/vijaykumar/Desktop/project2/Task%20Description%20and%20Checklist.md) (lines 49–80):

| Column Index | Column Name | Type / Allowed Values | Description & Example |
| :--- | :--- | :--- | :--- |
| 1 | `Payer` | String | Payer name (`Cigna / EviCore`) |
| 2 | `Policy ID` | String | Policy identifier (`CMM-601`) |
| 3 | `CPT` | String (5 digits) | Procedure CPT code (e.g. `22551`) |
| 4 | `Procedure` | String | Official procedure title |
| 5 | `Condition/Indication` | String | Target clinical indication (e.g. `Cervical Radiculopathy`, `Cervical Myelopathy`, `Adjacent Segment Disease`) |
| 6 | `PA Required` | String (`Yes` / `Add On`) | Prior authorization requirement status |
| 7 | `Criterion ID` | String (e.g. `C1`, `C2`) | Deterministic unique criterion identifier within the CPT/Indication |
| 8 | `Medical-Necessity Criterion` | String | Plain-language clinical requirement statement |
| 9 | `Logic` | String (`AND` / `OR`) | Boolean operator governing this criterion relative to peers |
| 10 | `Threshold` | String | Specific duration or numerical threshold (e.g. `≥6 weeks`, `>3.5mm`, `>11°`, `—`) |
| 11 | `Documentation Required` | String | Specific medical documentation (e.g. `Physician note`, `MRI/CT report`, `Flexion/extension X-rays`, `Cotinine test`) |
| 12 | `Exception/Exclusion` | String | Applicable exceptions or unmanaged exclusion conditions |
| 13 | `Page` | Integer | Exact page number in `Cigna_ACDF.pdf` (1–39) |
| 14 | `Section` | String | Exact policy section title from TOC (e.g. `CMM-601.4: Initial Primary ACDF > Radiculopathy`) |
| 15 | `Source Text` | String | Verbatim excerpt from `Cigna_ACDF.pdf` |

## 4. Work Breakdown & Implementation Tasks

### Wave 1: Data Structuring & Ground Truth Generation

#### Task 1: Build Deterministic Ground-Truth Extraction & Dataset Script
- **File:** `scripts/generate_ground_truth.py`
- **Actions:**
  1. Define strict clinical criterion definitions for each of the 10 CPT codes across all covered clinical indications:
     - **Initial Primary ACDF (CPT 22551, 22552, 22554, 63075, 63076):**
       - Indication A: `Cervical Radiculopathy` (CMM-601.4, Page 11) — Daily functional pain impairment AND radicular pain disability AND physical exam findings (sensory/motor/reflex/Spurling) AND failure of >=2 conservative therapies for >=6 weeks (analgesics/steroids/PT/injections) AND cervical plain x-rays (flex/ext) AND concordant MRI/CT neural compression (herniated disc/stenosis/osteophyte) AND absence of unmanaged mental/behavioral disorders AND nicotine-free status (never-smoker or >=6 weeks cessation verified by cotinine testing).
       - Indication B: `Cervical Myelopathy` (CMM-601.4, Page 12) — Myelopathic symptoms (weakness/clumsiness/gait disturbance/bowel-bladder dysfunction) AND concordant exam findings (Hoffmann/Babinski/hyperreflexia/ataxia/clonus) AND concordant MRI/CT showing cervical cord compression or stenosis.
     - **Anterior Cervical Corpectomy (CPT 63081, 63082):**
       - Section `CMM-601.5` (Pages 13–14) — Severe cord compression extending behind vertebral body not accessible via discectomy alone, OR multi-level cervical stenosis requiring vertebral body resection, with neurological symptoms and concordant imaging.
     - **Adjacent Segment Disease (CPT 22551, 22552, 22554, 63075, 63076):**
       - Section `CMM-601.7` (Pages 19–21) — Prior fusion at adjacent level with symptomatic new radiculopathy/myelopathy failing conservative care, documented by imaging showing compression or instability at the adjacent segment.
     - **Repeat ACDF at Same Level (CPT 22551, 22554, 63075):**
       - Section `CMM-601.6` (Pages 15–18) — Pseudoarthrosis / non-union after >=12 months with persistent pain OR hardware failure / graft dislodgement with instability.
     - **ACDF Following Failed Disc Arthroplasty (CPT 22551, 22554, 63075):**
       - Section `CMM-601.8` (Pages 22–25) — Explantation and conversion to fusion due to device failure, loosening, heterotopic ossification, or recurring neural compression.
     - **Anterior Osteotomy / VCR (CPT 22220):**
       - Section `CMM-601.2` (Pages 6–7) — Fixed cervical kyphotic deformity or converting fixed to mobile, cannot be corrected by fusion alone, AND ACDF criteria met.
     - **Add-on Codes & Instrumentation (CPT 22845, 22853, 22552, 63076, 63082):**
       - Section `CMM-601.1` & `Codes (CMM-601)` (Pages 28–30) — Performed in conjunction with primary cervical fusion / corpectomy at each qualifying interspace or vertebral segment.
  2. Implement direct verification against `hierarchical-processing/ACDF_toc_output_new.json` and `data/raw/Cigna_ACDF.pdf` text to ensure verbatim quotes and exact page citations.
  3. Ensure directory `data/ground_truth/` exists.
  4. Write out `data/ground_truth/Policy_Ground_Truth.xlsx` using `pandas` and `openpyxl`.
  5. Apply professional Excel formatting:
     - Header row: Dark Navy fill (`#1F4E79`), Bold White text, auto-filter enabled.
     - Column widths automatically adjusted to fit longest cell content with a ceiling.
     - Freeze top row (pane frozen at `A2`).
     - Text wrap enabled on text-heavy columns (`Medical-Necessity Criterion`, `Source Text`).

### Wave 2: Automated Verification & Ground Truth Audit

#### Task 2: Build Ground Truth Verification Suite
- **File:** `scripts/verify_ground_truth.py`
- **Actions:**
  1. Load `data/ground_truth/Policy_Ground_Truth.xlsx`.
  2. **Schema Audit:**
     - Validate presence and exact sequence of all 15 columns.
     - Verify no unexpected or missing column headers.
  3. **Data Completeness Audit:**
     - Verify zero null, empty, or whitespace-only cells across mandatory fields (`Payer`, `Policy ID`, `CPT`, `Procedure`, `Condition/Indication`, `PA Required`, `Criterion ID`, `Medical-Necessity Criterion`, `Logic`, `Page`, `Section`, `Source Text`).
  4. **CPT Coverage Audit:**
     - Assert that all 10 CPT codes (`22551`, `22552`, `22554`, `63075`, `63076`, `63081`, `63082`, `22220`, `22845`, `22853`) have at least 1 explicit criterion row.
  5. **Logic & Rule Audit:**
     - Assert `Logic` is strictly one of `AND`, `OR`, or `—`.
     - Assert `PA Required` is strictly `Yes` or `Add On`.
  6. **Citation & Page Verification:**
     - Cross-check every row's `Page` number against the actual page range of the referenced `Section` in `hierarchical-processing/ACDF_toc_output_new.json`.
     - Cross-check `Source Text` substrings against the policy text to guarantee zero synthetic hallucination.
  7. Output pass/fail status with total criterion count and coverage statistics.
