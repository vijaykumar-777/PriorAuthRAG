# Phase 5.2 Plan: Generic Clinical Patient Schema & Synthetic Test Generator

## 1. Executive Summary & Objective

Build a reusable, payer-agnostic generic clinical patient schema and generate a comprehensive suite of **50 synthetic test cases** across the 10 selected CPT codes, directly anchored to [`data/ground_truth/Policy_Ground_Truth.xlsx`](file:///home/vijaykumar/Desktop/project2/data/ground_truth/Policy_Ground_Truth.xlsx).

This suite establishes both **case-level** and **criterion-level** gold-standard expected determinations across all 8 failure modes and edge cases, providing the exact inputs and ground-truth comparisons for Phase 5.3 (Pipeline Runner) and Phase 5.4 (Automated Evaluation & Metrics).

---

## 2. Locked Context & Invariants

From [`.planning/phases/5.2-CONTEXT.md`](file:///home/vijaykumar/Desktop/project2/.planning/phases/5.2-CONTEXT.md):
- **Case Volume:** Exactly **50 synthetic test cases** covering all 10 CPT codes (`22551`, `22552`, `22554`, `63075`, `63076`, `63081`, `63082`, `22220`, `22845`, `22853`).
- **8 Test Case Archetypes:**
  1. `All Criteria Met` (Expected: `MET`)
  2. `One Criterion Failed` (Expected: `NOT MET`)
  3. `Information Missing` (Expected: `UNKNOWN`)
  4. `Wrong Condition / Indication` (Expected: `NOT MET`)
  5. `Boundary Condition` (Threshold edge testing, e.g. 5 weeks vs 6 weeks, 3.0mm vs 3.5mm)
  6. `Exception / Urgent` (Expected: `MET` via clinical emergency bypass)
  7. `Conflicting Evidence` (Expected: `CONFLICT` / `REVIEW`)
  8. `Missing Supporting Document` (Expected: `MISSING DOCUMENT` / `UNKNOWN`)
- **Payer-Agnostic Schema Invariant:** The patient schema must only contain realistic EHR observations (symptoms, vitals, exam signs, imaging findings, lab results). Zero policy rules, policy citations, or answer keys may appear inside patient clinical fields.
- **Dual-Layer Deliverables:**
  - Multi-sheet Excel: `data/synthetic_cases/Synthetic_Test_Cases.xlsx` (`Case_Level` and `Criterion_Level` sheets).
  - Standalone Patient JSON files: `data/synthetic_cases/cases/SYN-001.json` through `SYN-050.json`.
  - Standalone EHR narrative text files: `data/synthetic_cases/documents/SYN-XXX/` (`physician_note.txt`, `mri_report.txt`, `pt_notes.txt`, `lab_report.txt`).

### B. Excel Sheet 1: `Case_Level` (11 Columns)
1. `Case ID` (e.g. `SYN-001`)
2. `Payer` (`Cigna / EviCore by Evernorth`)
3. `Policy ID` (`CMM-601`)
4. `CPT` (5-digit code)
5. `Procedure` (Full procedure title)
6. `Condition` (Clinical indication)
7. `Test Case Type` (One of the 8 archetypes)
8. `Expected Overall Result` (`MET`, `NOT MET`, `UNKNOWN`, `CONFLICT`)
9. `Expected Missing Information` (Specific field missing, or `—`)
10. `Expected Exception` (Urgent bypass triggered, or `—`)
11. `Notes` (Detailed rationale for the expected determination)

### C. Excel Sheet 2: `Criterion_Level` (6 Columns)
1. `Case ID` (e.g. `SYN-001`)
2. `Criterion ID` (e.g. `C1`, `C2`...)
3. `Criterion` (Specific clinical requirement description)
4. `Expected Result` (`MET`, `NOT MET`, `UNKNOWN`)
5. `Patient Evidence` (Exact clinical fact or excerpt from patient record)
6. `Notes` (Clinical evaluation note)

## 4. Implementation Tasks & Wave Breakdown

### Wave 1: Schema Definition & Synthetic Matrix Formulation

#### Task 1: Generic Patient Schema Model
- **File:** `scripts/patient_schema.py`
- **Actions:**
  - Define Python data model / Pydantic schema for generic patient records.
  - Implement serialization to/from JSON and validation helper methods.
  - Ensure zero payer-specific or policy-specific hardcoded fields.

#### Task 2: Synthetic Case Specification Matrix (50 Cases)
- **File:** `scripts/case_matrix.py`
- **Actions:**
  - Define the complete 50-case distribution matrix across the 10 CPT codes:
    - `22551` (8 cases): Radiculopathy (All Met, 3-wk PT Fail, Cotinine positive Fail, Missing X-rays Unknown, Conflicting MRI, Urgent Myelopathy Bypass), Myelopathy (All Met), Adjacent Segment Disease (All Met).
    - `22552` (4 cases): Multi-level (All Met, Add-on level asymptomatic Fail, Missing add-on MRI Unknown, Boundary 1-level only).
    - `22554` (5 cases): Radiculopathy (All Met, Conservative Fail, Missing Notes, Wrong axial neck pain only, Boundary threshold).
    - `63075` (5 cases): Single discectomy (All Met with fusion, Standalone without fusion Fail, Boundary, Conflicting, Urgent).
    - `63076` (4 cases): Add-on discectomy (All Met, Missing document, Wrong level, Add-on without primary Fail).
    - `63081` (6 cases): Corpectomy (All Met retrovertebral compression, Osteophytes only Fail, Trauma/Urgent bypass Met, Standalone without fusion Fail, Missing MRI, Boundary <1/2 vertebral body).
    - `63082` (4 cases): Add-on corpectomy (All Met, Missing imaging at segment 2, Standalone Fail, Boundary).
    - `22220` (5 cases): Osteotomy/VCR (All Met fixed kyphosis, Mobile/flexible deformity Fail, Missing alignment X-rays, Correctable by fusion alone Fail, Urgent).
    - `22845` (5 cases): Anterior instrumentation (All Met 2-3 segments, Standalone without fusion Fail, Missing op plan, 4-segments wrong code boundary, All Met).
    - `22853` (4 cases): Interbody cage (All Met with arthrodesis, Without arthrodesis Fail, Missing document, All Met).
  - Define deterministic criterion-level expected evaluations for every case against `Policy_Ground_Truth.xlsx`.

### Wave 2: Case & Document Generator Engine

#### Task 3: LLM-Assisted Narrative Document & Case Generator
- **File:** `scripts/generate_synthetic_cases.py`
- **Actions:**
  - Load the 50 case definitions from `scripts/case_matrix.py` and criteria from `Policy_Ground_Truth.xlsx`.
  - For each case, generate the structured `SYN-XXX.json` record.
  - Use Groq API (`qwen/qwen3.8-27b`) with prompt engineering to write realistic EHR narrative documents:
    - Consultation physician note with HPI, ROS, physical exam, and assessment/plan.
    - Radiology reports (MRI cervical spine, cervical spine dynamic X-rays).
    - Physical therapy discharge summary / flow sheet.
    - Urine toxicology / cotinine laboratory report.
  - Include built-in deterministic templates as immediate fallback in case of API rate limiting or timeout.
  - Write files to `data/synthetic_cases/cases/` and `data/synthetic_cases/documents/SYN-XXX/`.
  - Compile and write `data/synthetic_cases/Synthetic_Test_Cases.xlsx` with formatted `Case_Level` and `Criterion_Level` sheets.

### Wave 3: Audit & Integrity Suite

#### Task 4: Automated Verification Script
- **File:** `scripts/verify_synthetic_cases.py`
- **Actions:**

  - Audit `Case_Level` sheet (exactly 50 rows, all 11 columns, zero nulls).
  - Audit `Criterion_Level` sheet (all cases mapped, all 6 columns, valid `MET`/`NOT MET`/`UNKNOWN`).
  - Verify all 50 JSON files exist in `data/synthetic_cases/cases/` and validate against `patient_schema.py`.
  - Verify all EHR documents exist in `data/synthetic_cases/documents/SYN-XXX/`.
  - Check distribution balance: all 10 CPTs represented, all 8 archetypes represented.
  - Check logical consistency: any case with a `NOT MET` criterion must have overall `NOT MET`, any case with an `UNKNOWN` criterion must have overall `UNKNOWN`, etc.
  - Check zero-leakage invariant: ensure no policy IDs, criterion IDs, or payer approval rules appear in patient clinical text.
